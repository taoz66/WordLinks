# WordLinks 架构与维护

本文档对应当前独立项目源码结构，面向开发者与 Agent 维护使用。

## 技术栈与构建脚本

- **工程与语言**：SwiftPM 工程（`Package.swift`），Swift tools 6.0 / Swift 5 language mode，最低系统 macOS 14.0，UI 使用 SwiftUI + AppKit，Markdown 解析使用 `swift-markdown` 0.5.0（精确版本锁定于 `Package.resolved`），词形数据库通过 `CSQLite` 只读访问。
- **入口**：[ReadingToolDailyApp.swift](../Sources/ReadingToolDaily/ReadingToolDailyApp.swift) 初始化 `ReadingLibraryStore`、`AISettingsStore`、语言与外观状态后注入主窗口与设置窗口；资料打开失败时展示错误，不覆盖写空资料。
- **打包与签名**：
  - `Scripts/build-app.sh`：使用系统 Xcode 26+ SDK（若全局版本较旧则回退 `build/AppleDeveloperTools/CommandLineTools`）编译 release，强制校验 `FoundationModels` 可导入，组装 `build/Wordlinks.app`（原子替换可执行文件）、安装资源与原生分层/静态图标并签名。
  - `Scripts/sign-app.sh`：复用 `~/Library/Application Support/ReadingToolDaily/CodeSigning/` 中稳定的本地证书签名并严格校验（`codesign --verify --deep --strict`）；签名异常即中止，不自动换证或退回 ad-hoc。
- **测试入口**：`Scripts/test.sh`（Xcode 26+ 下直接调用原生 `swift test`，旧 Xcode 环境自动回退混合工具链）；`Scripts/verify-ui-layout.sh` 可导出原生布局检查截图至 `build/UIInspection/`。

## 资料结构与索引边界

默认根目录为 `~/Library/Application Support/ReadingToolDaily/`（可通过 `READINGTOOL_DAILY_DATA_DIR` 覆盖，但该变量不隔离 `UserDefaults`、Keychain 与 `CodeSigning/`）：

```text
ReadingToolDaily/
├── profiles.json                  # 档案索引与当前档案 ID
├── Profiles/<profile UUID>/
│   ├── library.json               # ProfileArchive(version: 1)
│   ├── Articles/<article UUID>/<source filename>
│   ├── Backups/*.json             # 最近十份 library.json 自动备份
│   └── intensive-reading.json     # 每篇文章/语言的精读译文与对齐缓存
├── LocalCollections/              # 可选：仅本机持有的个人文章集合（不入公开库）
└── CodeSigning/                   # 机器稳定的签名证书与专用 keychain
```

- **Unicode 偏移边界**：持久化 `StudyCard.start/end` 与 `LibraryArticle.readOffset` 均使用 Unicode scalar 偏移；AppKit `NSTextView`/`NSRange` 使用 UTF-16 code unit，仅在明确边界调用既有转换函数。署名（`ReaderArticleByline`）通过标题分隔行间距绘制，精读（`IntensiveRenderDocument`）通过 `sourceSegments` 映射显示范围，均不改变 `article.text` 字符坐标。
- **文件同步与脱离状态**：以 0.75s timer 检查关联或托管文件变化（含外部原子替换）；文本变化后调用 `ArticleRevision` 重定位卡片与阅读位置，定位失败时设置 `isDetached = true` 并保全历史例句快照与卡片记录。
- **内置资源**：`Resources/Language/lexicon.sqlite3` 以只读模式打开；`Resources/Licensed/GlobalVoices`（5 篇，CC BY 3.0）、`Resources/Licensed/Wikipedia`（30 篇，CC BY-SA 4.0）与 `Resources/Licensed/PLOS`（15 篇，CC BY 4.0）共 50 篇内置文章保留集合/文章 UUID 与各自许可声明，仅在首次投放或匹配已知未编辑旧 hash 时更新；`Resources/Licensed/intensive-reading.json` 随包内置权威高质量精读数据，`ReadingLibraryStore.intensiveTranslations` 读取该资源作为离线秒开基底，用户 Profile 下的自定义译文优先覆盖；若 `rootURL/LocalCollections/*/catalog.json` 存在则一并加载本机私有集合。

## 内联编辑与 CSV 导出事务

- **按记录 ID 更新字段**：`ReadingLibraryStore.updateCardFields(profileID:cardIDs:field:value:expectedValue:)` 与 `applyCardFieldEdit` 独立于 `saveCard`，支持脱离原文的卡片，不触发文件同步或锚点重建。`StudyInlineEditCoordinator` 每窗口一份，编辑目标锁定 `profileID + cardIDs + field`，输入使用编辑器独立 Undo，提交后向窗口系统 `UndoManager` 登记整体事务（失败以纯簿记逆操作回滚并保留草稿提示重试）。
- **固定快照导出**：`StudyExportSnapshot.make` 先终止窗口内联编辑，再固定档案、范围、语言与公历 `en_US_POSIX` 时区；导出过程由 `StudyLibraryExporter` 加锁防重入。`StudyExportSavePanelDelegate` 在确认前预建议编号，`StudyExportWriter` 在同目录写临时文件后通过 `NSFileCoordinator` 复查目标身份完成写入。菜单与快捷键通过 `@FocusedValue(\.studyLibraryExport)` 限定到当前活动积累窗口。

## AI 架构与并发安全

- **生效配置与修订号**：`AISettingsStore` 维护当前生效服务与修订号。每次请求绑定配置修订号，切换服务、账号、目标语言或关闭弹出框后，迟到结果不得提交。
- **Keychain 与隐私边界**：
  - `ReadingToolDaily.AI` / `ReadingToolDaily.AIProfiles` 存自定义 API 密钥（无需认证时不读写密钥）；
  - `ReadingToolDaily.ChatGPT` 存动态客户端注册、刷新/访问令牌（仅绑定 `127.0.0.1` loopback OAuth，Responses 请求设置 `store: false`、`stream: true`，仅 `response.completed` 才提交成功）；
  - `ChatGPTAuthDiagnostics` 仅记录固定 stage/reason 代码与 HTTP 状态，不记录 URL、令牌或内容。
- **精读模型池**：`IntensiveReadingModelPool` 按 `(profileID, articleID, articleText, targetLanguage)` 复用 `IntensiveReadingModel`，`synchronizeScope` 幂等同步当前作用域；每批 4 句、最多 3 批并发。Apple Intelligence 接入每次新建 `LanguageModelSession` 串行排队并校验返回句 ID，不裁切源文或回退其他服务。

## 界面、工具栏与动效关键实现

- **工具栏与标题几何**：`NavigationSplitView` 移除自动 `.sidebarToggle`，在根工具栏前导位置声明一次 `library.sidebar`；`contentColumn` 不设标题，阅读文章时由 `detailTitleToolbar` 在详情栏使用 `LibraryColumnToolbarTitle`（`library.detailTitle`，`fillsColumnWidth: true`，macOS 26+ 隐藏共享玻璃背景），并由 `LibraryToolbarGeometry` 读取详情 split 列左缘、右侧按钮前缘与标题边界同步更新 `NSToolbarItem.view` 的 `widthAnchor`（`.defaultLow` 优先级）及内部 `label.frame`，不向 SwiftUI 回写每帧状态。
- **专注阅读与分栏协调**：`ReaderFocusWindow` 识别普通（`articleReaderText`）与精读（`intensiveArticleReaderText`）两类文本视图，沿祖先路径通过单个 AppKit `NSAnimationContext` 组折叠/恢复库栏（退出时如双栏同时恢复则分两阶段先恢复列表栏再恢复侧栏，并在恢复前通过 `prepareSplitExpansionWindowFloorIfNeeded()` 临时放宽最小窗口宽度至 420 pt）；3 秒空闲隐藏工具栏与红黄绿按钮时，通过 `additionalSafeAreaInsets.top` 补偿 chrome 高度差以消除正文跳动。窗口 chrome 仅在精读按钮的 `bounds ∩ visibleRect` 精确命中区提供「重新生成」菜单。
- **缩放与重排优化**：`CardAwareTextView` 启用非连续排版并在 820 pt 满宽居中区间关闭 `widthTracksTextView`；`ReaderSplitAnimationCoordinator` 协调长文（`> 2,200` UTF-16 字符）在分栏动画完成后统一刷新边距并叠加 `.fade` 过渡；`IntensiveDocumentRenderer` 按内容与样式键缓存已渲染文稿。
- **原生表单与控件**：`NativeLibraryControlBar` 在 macOS 26+ 使用 `safeAreaBar` + `scrollEdgeEffectStyle(.soft)`（macOS 14 回退 `safeAreaInset` + `.bar`）；`SettingsWindowView` 测量分组表单真实高度并适配当前屏幕可用区，其中的阅读风格控件 `ReadingStylePicker` 包装原生 `NSSegmentedControl` 实现四项等宽铺满整行；`SheetViewport` 在展示前设定导入（`560×600` / 批量 `1040×740`）与模板（`620×460`）首选尺寸。
